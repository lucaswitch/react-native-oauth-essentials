Errors

Every error the library can produce: the codes the promises reject with, which method rejects with which code, the errors without a code and the warnings shown in development.

How errors work​

  • Cancellation is not an error. When the user dismisses the UI, methods resolve { type: 'CANCELLED', data: null } (CancelledCredentialResult).
  • Errors reject with an Error that has a code from CredentialError and the native error text in message (OauthEssentialsError).
  • Check the code with isCredentialError instead of reading error.code on unknown. message is meant for logs: it comes from the OS or the provider, may change between versions and is not translated.
import { googleSignIn, isCredentialError, CredentialError, CredentialsType } from 'react-native-oauth-essentials';

async function signInWithGoogle() {
  try {
    const result = await googleSignIn({ mode: 'button' });
    if (result.type === CredentialsType.CANCELLED) return; // the user closed the UI
    await api.signInWithGoogle(result.data.idToken);
  } catch (e) {
    if (!isCredentialError(e)) throw e;
    switch (e.code) {
      case CredentialError.CONFIGURATION_ERROR:
        console.error(e.message); // a bug in the app setup, the message says what to fix
        break;
      case CredentialError.NOT_SUPPORTED_ERROR:
        showMessage('Update Google Play Services to sign in with Google.');
        break;
      case CredentialError.NO_SIGN_IN_AVAILABLE:
        showMessage('Add a Google account to this device to continue.');
        break;
      case CredentialError.BROWSER_UNAVAILABLE:
        showMessage('Could not open the sign in page. Try again.');
        break;
      default:
        report(e.code, e.message);
        showMessage('Sign in failed. Try again.');
    }
  }
}

CONFIGURATION_ERROR​

The app is misconfigured. It is a bug in the app setup, not something the user can fix: the message says exactly what to change.

CausePlatformMethodsFix
No Google iOS client id: none passed, no GIDClientID in Info.plist and no GoogleService-Info.plist in the appiOSgoogleSignIn, googleSilentSignInPass { iosClientId }, or set it in the Expo plugin / Info.plist (see Google client ids)
The reversed iOS client id is not in CFBundleURLTypes > CFBundleURLSchemes (the message has the exact scheme)iOSgoogleSignInAdd the URL scheme to Info.plist (REVERSED_CLIENT_ID of GoogleService-Info.plist), or use the Expo plugin
No Google web client id: none passed, no com.oauthessentials.GOOGLE_WEB_CLIENT_ID meta-data and no default_web_client_id from FirebaseAndroidgoogleSignIn, googleSilentSignIn, hybridSignInPass { webClientId }, or set it in the Expo plugin / AndroidManifest
redirectUri has no schemeBothoauthSignInUse a full uri like com.example.app://oauth/callback, or leave it out to use OAUTH_REDIRECT_URI
tip

Without these checks GoogleSignIn on iOS raises a native exception that crashes the app. The library validates them first, so you get a rejection instead.

NO_SIGN_IN_AVAILABLE​

There is nothing to sign in with. Show the normal sign in screen.

NO_ACTIVITY_ERROR​

There is no screen to present the sign in UI from: no current Android Activity, or no iOS view controller attached to a window. It usually means the method was called during app start before the first screen, or while the app is going to the background.

PlatformMethods
AndroidEvery method with UI: googleSignIn, googleSilentSignIn, getPassword, passwordSignIn, appleSignIn, hybridSignIn, createPassKey, getPassKey, oauthSignIn
iOSgoogleSignIn, oauthSignIn

SIMULTANEOUS_CALL_ERROR​

iOS only. A method was called again while its previous call is still pending. The new call rejects and the pending one keeps going, so this is usually a double tap: ignore it, or disable the button while the promise is pending.

The calls that share a lock are listed in Methods. A pending passkey AutoFill request (getPassKey({ mediation: 'autofill' })) does not block other passkey calls: it resolves CANCELLED instead.

NETWORK_ERROR​

oauthSignIn with tokenEndpoint: the token request could not be sent or did not get a response (offline, DNS, TLS). The original error is in error.cause. An HTTP error response is an INVALID_RESULT_ERROR instead.

Errors and events​

addCredentialFailureListener receives { code, message } for the rejections of googleSignIn, googleSilentSignIn, getPassword, appleSignIn, hybridSignIn, createPassKey, getPassKey and the Android rejections of passwordSignIn. It is not called for:

  • SIMULTANEOUS_CALL_ERROR;
  • the iOS NOT_SUPPORTED_ERROR below iOS 16 and the iOS missing requestJson error (passkeys);
  • signOut, getAppleIdCredentialState, cancelPassKeyAutoFill and oauthSignIn, which never emit events.

Errors without a code​

These do not have a CredentialError code, so isCredentialError returns false for them.

ErrorWhenFix
Error: "react-native-oauth-essentials does not work in Expo Go…"Thrown when the library is imported in Expo Go, which does not contain its native codeUse a development build: npx expo run:ios / npx expo run:android or eas build --profile development (see Expo)
Error: "the native module "OauthEssentials" was not found…"Thrown on import when the app binary does not contain the library: it was not rebuilt after installing (reloading Metro is not enough), pod install was not run, or the New Architecture is offRun pod install in ios/, rebuild the app and enable the New Architecture
Rejection with code 'CANCELLED': "Module is being invalidated"Android: a pending appleSignIn / oauthSignIn browser session when the React Native instance is destroyed (e.g. a reload in development)Nothing: the JS that was waiting is gone too

Development warnings​

In development (__DEV__) the library logs a console.warn once per method and option, prefixed with [react-native-oauth-essentials] <method>:. They do not change the result and are not shown in release builds.

WarningMethodsMeaning
"<option>" is ignored on iOS. / on Android.googleSignIn, googleSilentSignIn, hybridSignIn, appleSignIn, oauthSignInThe option has no effect on this platform (see the Platform column in Types)
the Google client id is ignored on iOS…hybridSignIniOS hybridSignIn offers Apple ID and passwords, not Google
does nothing on iOS: set textContentType on your inputs…passwordSignIniOS has no API to save a password without an associated domain
"preferImmediatelyAvailableCredentials: false" is ignored on iOS…createPassKey, getPassKeyiOS modal requests only offer passkeys on the device
"mediation: 'autofill'" is ignored on Android.createPassKey, getPassKeyAutoFill passkeys are iOS only
additionalParameters.<key> is ignored: the library sets it…oauthSignInresponse_type, client_id, redirect_uri, state, code_challenge and code_challenge_method cannot be overridden
